How does File A ↔ File B comparison work?

The existing matching engine first finds an accepted File A ↔ File B identity pair. Your condition then compares the two selected fields inside that matched pair. You can optionally require the selected File A field to exactly match an additional value or text. Leave the optional value blank when you only want the A ↔ B field comparison. It does not compare unrelated records. A verified duplicate stays in DUPLICATE RECORDS; a rule can add a review flag when needed.
